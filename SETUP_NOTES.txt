ProjectPilot — Windows setup (important information)
=====================================================

What the setup does
-------------------
• Creates a Python virtual environment (.venv) in this folder
• Installs backend Python packages from backend\requirements.txt
• Runs npm install in the frontend\ folder
• Copies .env.example to .env if .env does not exist yet (you must edit secrets afterward)

What this is NOT
----------------
• This is NOT a full Windows installer (no MSI / no bundled Python / no bundled Node.js).
• Python 3.11+ and Node.js (npm) must ALREADY be installed and available on your PATH.
• ProjectPilotSetup.exe only opens a console that runs built-in setup (--run-setup). No separate script file is required.

After setup — how to run the app
---------------------------------
• From the repo folder: double-click run.bat, or run:  .\.venv\Scripts\python.exe tools\dev_server.py
• That starts the API (port 8000) and the Vite dev UI (port 5173). See README.md for URLs and .env details.

After you update the folder (git pull / copy new files)
--------------------------------------------------------
• Optional check:  python tools\verify_setup.py
• Then start again with run.bat or tools\dev_server.py as above.

Network and other failures
----------------------------
• pip and npm need internet access to their registries. If something fails, it is not always an “internet error”.
• Disk space, folder permissions, antivirus blocking, corporate proxy, or corrupted caches can all cause failures.
• Read the red error text in the setup window and fix the reported issue (PATH, permissions, etc.).

Security and who is “admin”
----------------------------
• After install, edit .env: set JWT_SECRET_KEY and ADMIN_EMAIL / ADMIN_PASSWORD for the first login on THIS machine.
• Each deployment / customer environment should use its own secrets and its own Admin → Users list.
• The product does not lock “system owner” to one person by license; access is controlled by your .env and user accounts you create.
